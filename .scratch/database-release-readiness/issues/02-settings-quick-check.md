# 02: 在 Settings 提供快速数据检查

**What to build:** 用户在 Settings 主动检查本地数据库，可取消、查看结果并保存不含私人内容的诊断报告。

**Blocked by:** None (can start immediately). 耗时验收引用 01：建立数据库性能基线的报告，不阻塞实现开始。

**Status:** implemented-pending-acceptance

- [ ] 从 Settings 到 Tauri、应用协调和存储层形成完整路径；只提供快速检查，不提供完整检查或自动修复。
- [ ] 检查应用数据库版本、必需表和字段，执行 quick_check、foreign_key_check，并验证学习状态、日期与 JSON 等明确列出的格式规则。
- [ ] 从应用选定的数据目录以不带 CREATE 的独立只读连接打开数据库，不接收任意数据库路径，不调用迁移初始化；检查前后数据与 schema 不变。
- [ ] 同次数据库检查使用一致读取视图；缺表或无法读取导致后续检查无法执行时标为未完成，不能当作通过。
- [ ] 后台执行、单活动任务、任务 ID 隔离、分阶段进度、有限锁等待、取消及退出清理完整；SQLite 执行和 Rust 遍历均能响应取消，结束后释放事务和连接。
- [ ] 区分未发现异常、发现问题、未完成/取消；说明快速检查的覆盖范围，不声称它证明历史数据未丢失。
- [ ] 不以现存 Encounter 重建或验证历史匿名统计，不将 Starter Vocabulary Item 没有 Encounter 判为异常；遵守既有身份与删除规则。
- [ ] 通过原生保存选择器导出诊断报告；仅包含允许的版本、阶段、统计与问题代码字段，不含词汇、上下文、URL、凭据、绝对路径或原始错误，不自动上传。
- [ ] 测试正常库、缺表、外键异常、非法字段、损坏文件、锁等待、重复触发、取消和报告脱敏；复用现有摘要能力但避免混合不同快照。
- [ ] 以 01 的数据和运行预算验证检查耗时、界面响应及对保存操作的影响；启动失败时的恢复入口和备份恢复不在范围内。
