# 03: 优化词汇保存时的身份匹配

**What to build:** 大词库中保存 Vocabulary Item 时，候选身份匹配避免读取全部词汇，同时保持现有词汇身份与合并行为。

**Blocked by:** 01：建立数据库性能基线

**Status:** implemented-pending-acceptance

- [ ] 沿实际 capture 身份候选调用路径测量，不能仅凭已有 dedupe_key 查询索引推断无需优化。
- [ ] 把候选筛选尽量下推至 SQL；只有查询计划和基线证明需要时增加索引，附对应迁移与历史数据兼容验证。
- [ ] 保持规范化词形加源语言的身份规则、auto 源语言消歧、多目标语言译文共享身份和合并逻辑。
- [ ] 覆盖已知/未知源语言、多个已知语言、不同目标译文、重复保存和 Achieved recapture；不误合并，保留 Encounter、Review、翻译快照及学习状态。
- [ ] 在同一基线场景比较优化前后耗时与结果；验证事务失败不留下部分身份合并。
- [ ] 把必要的正确性回归接入现有自动测试；保持公共行为兼容，不顺带实现云同步或重写整个存储层。
