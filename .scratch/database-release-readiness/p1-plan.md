# P1 数据库实现计划

状态：产品选择已收敛，完整计划待最终确认；尚未实施
更新日期：2026-09-16

## 已确认

- 沿用 Windows 首发、本地无账号、共享 Rust 核心与三平台 CI 的方向。
- 备份与恢复留在后续 TODO，不作为本轮测试依赖；既有备份决策保留。
- 数据导出仅考虑 CSV，优先级较低；JSON 不在本轮范围。
- CSV 首版导出全部未 Achieve 的词汇，每行一个词，包含词汇、源语言、当前显示译文及其语言、学习状态、Encounter 次数、最近遇到时间。不包含上下文、复习历史和设置；不承诺完整恢复能力。
- 验收规模：1 万 Vocabulary Item / 10 万 Encounter；压力测试：10 万 Vocabulary Item / 100 万 Encounter。延迟指标待基线测量后确定。
- Settings 提供用户主动触发的数据健康检查和可保存诊断报告；不自动上传，报告默认不含词汇正文、上下文、来源 URL 或凭据。
- 首版仅实现快速检查，不提供完整检查入口；包括 quick_check、foreign_key_check 和基本应用规则检查。
- 用户主动卸载时删除正式版管理的数据库、设置、缓存和日志，未来应用管理备份也遵循此规则。升级内部卸载保留数据。保留用户另存到其他目录的 CSV 和手动文件，不影响开发版独立目录。卸载界面明确删除范围，失败必须报告；当前 NSIS 的询问保留行为需要调整。
- 性能先在当前 Windows 开发机建立基线，分别记录数据库查询与用户等待时间，再制定验收门槛；不先指定无测量依据的毫秒值。
- 首版验证 NSIS 安装包。现有 CI 执行代码、数据库规则与 CSV 自动测试；安装、升级、卸载在隔离 Windows 环境中演练并记录结果，暂不建设完整安装器自动化。

## 检查机制方案

复用 SqliteStore::database_summary，新增独立只读诊断路径，不调用会执行迁移的正常初始化路径。

1. 检查所需表、字段及应用数据库版本；无法读取时报告失败，不初始化空库。
2. 首版执行 quick_check 和独立 foreign_key_check；integrity_check 与完整检查入口暂缓。说明快速检查不覆盖全部唯一约束及索引一致性。
3. 检查能够从现存数据验证的业务约束，如状态值、可解析的日期/JSON、关联关系；不以存活 Encounter 重建或校验匿名历史总数，不把 Starter Vocabulary Item 没有 Encounter 判为错误。
4. 输出通过、发现问题、未完成/取消三类结果及各检查覆盖范围。SQLite 原始错误先映射和脱敏，不直接作为可分享报告。
5. 后台工作任务执行，单次只允许一个检查；明确读事务、锁等待上限、取消机制与退出时清理。进度按阶段展示，不捏造百分比。后台线程不意味着数据库写入不会被锁阻塞。
6. 首版只诊断、不自动修复。完整性检查通过不代表没有历史数据丢失，也不证明翻译或统计的业务正确性。

## 范围边界

- 正常可启动应用之外的启动失败诊断暂属 P0，不声称 Settings 入口能处理无法启动的数据库。
- P0 其余事项仍独立跟踪；完成本计划不等于全部发布条件通过。尤其卸载的数据目录隔离依赖必须解决后才可验收。
- 延迟门槛在基线阶段产生，写入测量报告后冻结，不能在优化后为通过验收随意放宽。

## 现有基础

- 三平台 CI 已有 Rust/前端测试及 Windows NSIS 构建，本轮补充覆盖。

## 模块设计

### 数据健康检查

- `crates/storage`：新增 diagnostics 模块与只读连接工厂，路径来自应用已选定的数据目录，不允许前端传入任意数据库路径；使用不带 CREATE 的只读打开方式，避免失败时创建空库。连接放在后台任务中使用，以单个读事务获得一致检查视图；不复用执行迁移的 SqliteStore::open。
- 复用摘要的数据定义和统计 SQL，不通过另一条连接混合不同时间点的数据。检查结果包含运行标识、检查时间、应用/SQLite/schema 版本、阶段、覆盖范围、计数和受限问题列表；文件大小仅作为采样信息，不能保证与事务快照完全同时。
- `crates/application`：协调检查顺序与结果分类；问题代码、数量和说明取代原始记录及错误文本。缺表导致后续项目无法执行时标记未完成，不伪装通过。区分异常发现与运行失败。
- Tauri：建议命令 start_database_check、cancel_database_check、get_database_check、save_database_check_report；名字可依现有习惯调整。仅一个活动任务，用任务 ID 防止旧事件覆盖新状态。数据库忙时有限等待并返回未完成；取消使用 SQLite 中断/进度机制，同时覆盖 Rust 数据遍历；所有结束路径释放事务与连接。
- UI：Settings 增加“检查数据”，按阶段显示进度及取消按钮，结束后显示结果并通过原生文件选择器保存脱敏 JSON 诊断报告。JSON 诊断报告不等于 JSON 词汇导出。前端保持可响应；只读检查可能短暂影响写提交，在基线阶段测量并设置运行预算，不能靠关闭数据库耐久性解决。
- 报告只包含允许字段，过滤绝对路径、用户名、词汇、上下文、URL、原始 JSON 与原始 SQLite 错误。无需逐条输出内部记录 ID。只检查已列明的规则，不新增历史数据推断。

### 性能与查询

- 合成数据生成器使用固定种子、临时文件数据库，包含多语言翻译、多次 Encounter、各学习状态与 Achieved 状态；不读取真实 guest.db。小型数据集用于正确性测试，大型数据集用于可重复测量。
- 测量 release 构建，记录提交、SQLite 版本、机器、数据规模、运行次数、首次与重复操作耗时、数据库耗时和端到端耗时。使用固定场景比较前后结果，记录中位数与尾部延迟；压力测试不作为相同延迟承诺。
- 已确认候选热点：identity::candidates 通过 all() 读取全部词汇再筛选；application::words_with_captures/list_words 对每词多次读取 Encounter，displayed_translation 对每词读取设置与翻译。find_word 已有 dedupe_key 索引查询不代表实际身份匹配路径没有全表读取。
- 优先把身份候选筛选移到 SQL，保留 auto 源语言消歧与合并规则；把列表计数、最近 Encounter、显示译文改为批量查询或聚合投影，设置每次请求只读一次。核对 EXPLAIN QUERY PLAN 后才添加索引。
- 当前前端搜索、排序、分页依赖全量列表。只有测量表明批量查询后仍达不到目标时才增加后端分页；届时同时实现搜索、排序、稳定次级排序键、总数和页面边界，不能只给 SQL 添加 LIMIT。
- 验收操作：保存词汇、打开列表、搜索、切页、快速检查；同时验证结果语义不变及界面响应。Starter Vocabulary Item 行为与 P0 初始化功能衔接，不把现有“有 Encounter 才展示”的行为盲目固化。

### CSV 导出（较低优先级）

- 存储层提供专用批量投影，排除已删除和 Achieved 词汇，包含 Learning/Mastered/Paused 及未来 Starter Vocabulary Item；不直接受当前 UI 搜索和分页影响。
- 每行一个 Vocabulary Item，字段为 vocabulary、source_language、translation、translation_language、learning_status、encounter_count、last_encounter_at。译文选择沿用当前显示语言规则；从未 Encounter 的词汇，次数为 0、最近遇到时间为空，不伪造时间。
- Rust CSV 库处理逗号、双引号、换行，UTF-8 输出兼顾 Excel；对可能被电子表格执行为公式的文本进行安全转义，文档说明它是面向阅读的导出，非无损还原格式。测试覆盖中文、空译文、多行文本和公式前缀。
- 在一致读事务中获取数据；原生保存对话框选择目标，通过暂存文件完成写入后发布结果，失败不留下看似成功的半份 CSV、不破坏已有文件。只有成功后显示导出条数。
- Tauri 管理文件选择与写入，不为前端开放任意文件系统访问。无既有原生保存能力时添加最小所需集成与权限。

### 卸载与 CI

- `apps/desktop/src-tauri/windows/installer-hooks.nsh`：用“主动卸载清理、更新保留”的明确分支替换当前保留数据问答。实现前核实所用 Tauri/NSIS 模板的升级标志及静默执行路径，不能猜测变量。
- 使用应用拥有的明确目录白名单，路径必须解析到当前用户的正式版目录；不扫描磁盘、不删除外部 CSV、开发目录或共享 WebView2 运行时。收集数据库附属文件、WebView 数据、缓存和日志的实际位置后更新清单。
- 用户确认卸载的页面明确告知删除数据。先停止应用并释放句柄，检查删除结果；失败时说明残留和重试方法，不能将部分清理报告为全部成功。未来备份清理能力在备份实现时接入。
- 自动测试并入现有三平台 CI。小数据正确性测试用于每次提交；完整性能报告在受控 Windows 环境生成，避免将共享 runner 的噪声作为毫秒级阻塞条件。大规模压力测试按需运行。
- NSIS 验证记录包含 OS、应用版本、安装包 SHA256、步骤及结果。只使用隔离 Windows 用户/虚拟机和合成数据；没有可用环境时明确保留人工验收项，不能用代码检查代替实机结果。
