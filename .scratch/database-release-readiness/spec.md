# 本地数据库发布准备清单

日期：2026-09-15
状态：待办规划，尚未实施

## 范围与现状

目标是发布供外部用户使用的开源、本地存储桌面应用。云账号与同步不属于首版本范围。本清单是发布建议，不是对现有实现已发生故障的断言；本次进行了代码与文档检查，没有运行测试或完整安全审计。

已具备：SQLite + rusqlite、操作系统应用数据目录、SqliteStore 封装、事务、外键、唯一约束、数据库迁移（当前版本 9）、较新数据库版本拒绝机制、部分历史迁移与回滚测试。

证据入口：apps/desktop/src-tauri/src/lib.rs、apps/desktop/src-tauri/tauri.conf.json、crates/storage/src/lib.rs、crates/storage/src/identity.rs、crates/storage/tests/sqlite_repository.rs、crates/storage/tests/vocabulary_log.rs、crates/sync/src/lib.rs。

## P0：建议在首次面向普通用户发布前完成

- [ ] **隔离开发、测试和正式数据。** 使用不同应用标识或明确的数据目录策略；测试使用临时数据库。验收：开发版与正式版同时安装时互不修改对方数据，升级正式版仍打开原数据库。检查 Windows AppData 与 LocalAppData 的选择并记录理由。
- [ ] **实现一致性备份和恢复。** 提供手动备份、恢复入口及数据库结构升级前备份。使用 SQLite backup API 或经验证的替代方案；恢复先校验候选文件的结构、外键、版本及应用数据格式，再停止数据库访问、保留原库并替换，失败可退回原库。验收：旧版备份可恢复升级，损坏或较新版本备份被安全拒绝，恢复后词汇、翻译、Encounter、Review、设置和统计一致。备份保留周期与 ADR 0004/0005 的删除语义一起说明。
- [ ] **完善升级发布门槛。** 在现有迁移与回滚测试上补齐所有承诺支持的历史版本夹具；覆盖重复打开、跨版本升级、失败后重试和较新数据库拒绝。明确最低支持版本。验收：迁移前后身份合并、翻译快照、关联记录、学习状态及匿名统计符合 ADR 0004–0006；失败后原数据可用。按版本拆分迁移属于维护性改进，不以重写现有迁移为发布前提。
- [ ] **提供数据库错误恢复流程。** 区分无法写入、磁盘满、锁冲突、损坏和版本不兼容；打开失败时不能自动删除或覆盖原库。验收：用户能获知问题并访问恢复入口；未提交写入不显示保存成功；保留原始文件供恢复。
- [ ] **确定本地模式 outbox 策略。** 当前保存操作写入 outbox，但同步模块尚未提供实际传输。选择在未启用同步时停止排队，或制定有界保留/合并策略；如将来启用同步，定义首次全量同步。验收：连续本地使用不会无界累积无用途的变更副本；清理不破坏撤销、迁移和永久删除语义。实施前核对所有引用，不直接清空队列。
- [ ] **验证持久性和多实例行为。** 明确只允许一个应用实例，或支持多个实例的锁等待与冲突处理；检查当前连接默认值后确定 busy timeout、journal 和 synchronous 策略。验收：写入中终止进程后重启只出现完整提交或完整回滚；第二实例不使保存静默失败。进程终止测试不能替代真实断电验证。
- [ ] **完成数据库隐私与开源发布检查。** 文档说明存储位置、默认是否加密、上下文和来源 URL 的保存、永久删除和备份残留的边界；确认实际数据库、备份和真实用户夹具不进入 Git 历史或发布包。现有 .gitignore 已忽略 *.db、*.db-wal、*.db-shm，仍需检查其他扩展名、journal 和备份产物。验收：发布包无私人数据，诊断日志默认不含词汇上下文或凭据。

## P1：公开测试阶段或首个稳定版本前完成

- [ ] **提供可移植的数据导出。** 优先带格式版本的 JSON，保留词汇、翻译、Encounter 和 Review 的关联；CSV 用于简单阅读。备份用于完整恢复，导出用于跨工具使用，两者分别定义。合并导入可随后实施，需明确去重与冲突规则。
- [ ] **建立规模测试并按证据优化查询。** 建议夹具为 1 万条词汇、10 万条 Encounter，并记录测试机器与延迟目标。重点检查 identity::candidates 全量读取词汇、列表、搜索、复习和统计；需要时改为 SQL 条件筛选、索引和分页。验收：主要交互满足约定延迟，且保持身份匹配语义。
- [ ] **补充数据健康诊断。** 按需运行 quick_check/integrity_check 和独立 foreign_key_check；报告 schema 版本、SQLite 版本、数据库体积与队列数量，不上传原始内容。避免每次启动执行高成本全库检查。
- [ ] **验证安装生命周期。** 对每个宣称支持的平台测试新装、升级、重装及卸载的数据保留行为；文档解释删除数据的方法。验收：升级不丢数据，卸载是否保留数据与说明一致。
- [ ] **把数据库验证接入发布 CI。** 使用合成夹具执行现有存储测试、历史版本迁移和备份恢复测试；记录 bundled SQLite 实际版本并跟踪依赖更新。先确认已有 CI 覆盖，补缺而不重复建设。

## P2：按产品需求决定

- [ ] 改名 guest.db：仅提高命名清晰度；改名必须兼容已有文件并处理两个名称同时存在的情况。
- [ ] 数据库加密：根据敏感性与威胁模型决定，同时设计密钥存储、备份和恢复；不是一般本地词汇应用的通用发布前提。
- [ ] WAL、连接池、专用数据库工作线程：在实际并发或界面阻塞测量后决定，不机械启用。
- [ ] 空间回收策略：根据删除后体积与维护耗时决定是否提供 VACUUM；不等同于承诺磁盘级安全擦除。
- [ ] 云同步：另立规格处理身份、认证、RLS、冲突、删除传播及离线行为，不阻塞本地版本发布。

## 建议顺序

数据目录隔离 → 备份恢复 → 升级验证与错误恢复 → outbox/多实例策略 → 隐私检查 → 发布演练。性能、导出与 CI 补缺可在上述事项推进时安排。
