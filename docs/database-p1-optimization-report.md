# P1 数据库优化报告

日期：2026-09-16。基线提交：873fe41fc866f2c7449b0036f292996bc1c7392b；优化结果来自当前未提交工作区。

## 测量方法

Windows x64；CPU 环境标识 Intel64 Family 6 Model 165 Stepping 2, GenuineIntel；SQLite 3.53.2；Rust release 构建。固定序列合成词汇，每词 10 个 Encounter、2 个目标语言翻译和 1 个 Review，包含 Learning/Mastered/Paused 与 Achieved。所有数据库在唯一临时文件中生成，未读取用户词库。正常规模重复 5 次，压力规模重复 3 次。

保存测量为存储层重复收藏同一个已有词；列表测量为完整 AppService 返回。Rust 中搜索/翻页模拟值不代表浏览器性能，另做浏览器测量。首次运行包含在统计中；样本量很小，使用中位数及样本最大值，不把它们当作生产环境 p95。运行期间机器还承担开发工作，结果不是隔离实验室基准。

## Ticket 03：词汇身份匹配

将按词形筛选候选词的全表读取改为 SQL 条件查询，并增加针对未删除词汇的 `(lemma, owner_scope)` 索引。保持规范化词形、源语言 auto 消歧、目标语言共享身份和合并引用的原有规则。索引在现有启动事务中幂等创建，不改变领域结构。

| 规模 | 保存基线中位数 | 优化后中位数 | 加速 | 优化前/后样本最大值 |
| --- | ---: | ---: | ---: | ---: |
| 1 万词汇 / 10 万 Encounter | 80.719 ms | 14.001 ms | 5.77 倍 | 84.234 / 43.653 ms |
| 10 万词汇 / 100 万 Encounter | 739.648 ms | 52.392 ms | 14.12 倍 | 782.465 / 343.370 ms |

较大样本仍有磁盘写入尾部波动，不能声称每次保存都达到中位数。现有身份合并、auto 消歧、翻译快照、撤销与失败回滚测试继续通过。

## Ticket 04：词汇列表

过去会为每词反复读完整 Encounter，并逐词读取设置和译文。现在在同一读事务中一次读取设置，聚合 Encounter 数量与最近时间，通过索引选取当前显示译文，返回完整列表投影。无 Encounter 的词汇可展示，为 Starter Vocabulary Item 保留正确语义；CSV 复用同一投影。

| 规模 | 列表基线中位数 | 优化后中位数 | 加速 | 优化前/后样本最大值 |
| --- | ---: | ---: | ---: | ---: |
| 1 万词汇 / 10 万 Encounter | 3,683.267 ms | 124.541 ms | 29.57 倍 | 4,970.736 / 125.629 ms |
| 10 万词汇 / 100 万 Encounter | 45,861.887 ms | 1,353.964 ms | 33.87 倍 | 47,675.163 / 1,393.842 ms |

正常规模达到了优化前声明的存储/应用层门槛：列表中位数低于 500 ms，保存低于 100 ms。无需为了本轮目标改为后端分页。十万词汇为压力规模，不适用同样门槛。

新增完整快速检查（结构、quick_check、外键和格式）的正常规模 5 次耗时为 449、566、762、655、520 ms，中位数 566 ms。身份匹配的实际查询计划为 `SEARCH words USING INDEX idx_words_identity_candidate (lemma=? AND owner_scope=?)`，随后仅对候选结果按 ID 排序。检查最大运行预算为 30 秒，锁等待最多 250 ms；超时/锁失败报告未完成。

## 浏览器界面测量

使用 Windows 上 Chromium 152 的本地开发预览，实际 WindowsApp、合成 Backend；每次测量包括两次绘制帧。数据已在内存，不包含原生 IPC、SQLite 或文件保存对话框。结果不能与 Rust 数值简单相加作为完整原生应用延迟。

| 规模 | 列表切换中位数 | 翻页中位数 | 搜索中位数 | 最大列表/翻页/搜索 |
| --- | ---: | ---: | ---: | ---: |
| 1 万词汇 | 28.5 ms | 25.6 ms | 39.5 ms | 93.4 / 40.0 / 40.0 ms |
| 10 万词汇 | 29.2 ms | 26.7 ms | 79.8 ms | 53.5 / 40.0 / 93.1 ms |

每次只渲染 10 行。Settings 的 Local data 区域已在浏览器检查布局和可达性。原生 WebView + IPC 的完整计时及安装生命周期仍需隔离 Windows 演练。

本次提交包含 Ticket 01–06 的实现，不表示全部验收项已关闭。已有一轮 Windows 适用 Rust 测试 209 项、前端测试 143 项通过；安装包已构建，但原生端到端操作与安装生命周期尚未实测。Ticket 07、08 按用户要求延期。

## 复现命令

运行 `cargo run --release -p vocab-application --example database_benchmark -- 10000 5`，压力规模把参数改为 `100000 3`。新输出同时包含快速健康检查耗时和实际身份候选查询计划。基线使用优化前可执行文件采集。

原始 Rust 样本位于 `.scratch/database-release-readiness/` 的 `baseline-10000.json`、`baseline-100000.json`、`optimized-10000.json`、`optimized-100000.json`。后续 `verification-10000.json` 用于新增完整快速检查的测量，不覆盖原始对照样本。

启动 UI 开发服务器，打开 `/src/test/database-performance.html`，点击 Run UI benchmark；追加 `?size=100000` 运行压力场景。该页面只用于开发验证，不是产品功能。
